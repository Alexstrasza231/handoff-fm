# 任务用量与新手首页（v0.1.2）

首页看三件事：两位刚做了什么、当前任务已记录多少用量、去哪里看详情。
点 **查看详情 → 过程记录 / 用量明细**；点角色可以筛选 Codex 或 DeepSeek 的过程记录。
**回放过程** 只播放记录，不执行工具。空白首页的 **看个例子** 是明确标注的静态示例。

默认统计最近一次 Codex 用户指令及明确关联的 DeepSeek 任务，详情还能切换 **会话累计**。
Tokens 是已记录的消耗，不是费用、账单、账户额度或余额。任务经过时间包含等待与工具执行，
不能解释为模型思考时间。工具次数按 `(人员, 会话, callId)` 去重。

## 数据从哪里来

- DeepSeek：读取现有 JSON 流的 `status / step_end / usage`，同一步骤替换，不同步骤相加。
  源头已经合计重试消耗，HandoffFM 不再叠加重试、结束事件。其 `inputTokens` 不含缓存，
  统一成含缓存输入；如果来源提供精确总量，可以在缺少缓存细项时确定输入。
  缓存细项和精确总量都不足时，总数留空。
- Codex：仅使用已启用项目的可信 Hook 提供的当前会话日志路径和任务 ID。`watch` 运行时
  增量、有界读取数字；每轮每个来源最多 256 KiB、最多四个来源，首次只读取末尾最多 2 MiB。
  只保留明确任务边界和非负用量计数，以观察到的累计差值计算任务消耗，不把整个会话总量
  当作当前任务用量。首次覆盖不完整时显示部分数据。
  [官方说明](https://learn.chatgpt.com/docs/hooks)明确指出日志格式可能变化；无法识别就不提供数字。

输入包含缓存，输出包含推理；缓存和推理都是子集，不额外加入总量。
缺失字段显示 **未提供 / 尚未采集**；**部分数据** 表示只知道部分已记录消耗。
晚启动 `watch` 不会补造此前数字；旧记录没有真实采样就显示未采集。

`.handoff-fm/usage-sources/`、`usage-turns/`、`usage-paths/` 是本地私有登记与检查点，包含路径、偏移、标识、
哈希与数字状态，不包含聊天或推理原文。只登记可信 Hook 给出的路径，不扫描其他会话。
已登记日志也会排除出普通文件快照和工具证据。过长行跳过，不把原文存入检查点。
日志替换或截断后保留此前已知消耗，标为部分数据，以后续新基线继续采集，不重算历史。
有界读取未找到任务边界时暂不归属，直到观察到明确边界。快照不可用时显示记录缺口，
不补造文件差异。重启收集器会恢复检查点。

## 任务关联、回放与分享

有真实父任务 ID 时传 `--parent-turn`。未传时，只有同一父会话存在唯一活动任务才能补齐；
没有活动任务或有歧义时，DeepSeek 调用保持未关联，只进入会话累计和未关联明细，
不计入当前任务。并发调用不会借用其他会话的任务。

回放只使用播放位置之前的采样。用量采样不会触发角色动作、交接或字幕。
同一采样以接收顺序的最新值为准，避免重连、重复事件与重启造成重复计数。

分享的 **用量数据** 默认关闭，CLI 可用 `--usage` 选择。预览和离线导出使用同一逻辑，
只导出白名单数字、完整度、来源及匿名化采样/任务标识，不导出日志路径和原文。
发布前人工检查自己选择的内容。
